## 3. Boot sequence

1. **`Plugin.Awake`** (BepInEx chainloader):
   - `FirstRun.Start` (Thunderstore build only: `extract/DeadlockExtract.exe` beside the DLL). It finds Deadlock (config
     *Deadlock folder*, env `DEADLOCKOFRAIN_DEADLOCK`, RoR2's own Steam library, Steam's path from `reg.exe query
     HKCU\Software\Valve\Steam`, `C:\Program Files (x86)\Steam`, then every library in `libraryfolders.vdf`; Deadlock is
     `steamapps/common/Deadlock` with `game/citadel/pak01_dir.vpk`) and starts the extractor as a hidden child process.
     The cache is then opened on the loading screen (step 2), and `DeadlockAudio.Init` waits for it too.
     Every place it looks is logged (`found Deadlock` / `not here`, Steam's registry path, the libraries in each
     `libraryfolders.vdf`); while the exe runs, its `extract.log` lines are copied into the BepInEx log as
     `[DeadlockExtract] ...` with a `Reading Deadlock: step n/total` line per step and the total time at the end.
   - **On screen:** `FirstRunOverlay` (IMGUI, so it draws while RoR2's UI is still loading; needs
     `UnityEngine.IMGUIModule` in the csproj) shows a box at the bottom left of the loading screen: the step, the
     percentage (it creeps within a step, so Abrams' ~4 min never looks frozen), the elapsed time and the last six
     lines. Hidden on normal starts (the exe ends within 3 s); fades 8 s after the work ends or Deadlock isn't found.
   - Otherwise (Melty build) `Plugin.OpenCache()` → `DeadlockCache.Open(dir)`: no `ready.json` means an error is logged and no heroes are built (the game still runs).
   - When the heroes can't be loaded, `FirstRun.Problem` holds why; `FirstRun.Init` shows it once in a `SimpleDialogBox` on
     the title screen (tokens `DLR_FIRSTRUN_*`, header `FirstRun.ProblemHeader`).
   - **Some heroes unreadable (v0.7.1, extractor 1.3.0):** `DeadlockCache.Open` reads `ready.json`'s `failed` list into
     `DeadlockCache.Failed`; `Survivors` skips those heroes ("hero X skipped: Deadlock could not be read for it (...)"),
     every other hero loads, and the same title-screen box says "<names> couldn't be read from this Deadlock version; the
     other heroes are ready". This works on Melty starts too (no FirstRun needed). Co-op stays safe: the mod-list entry
     names only the heroes built (§7.7), so a friend missing one is refused at the lobby.
   - **Since v0.7.2 a skipped hero keeps a locked red "!" tile** (`Content/MissingHeroes.cs`, creator 2026-10-19). It is a
     Commando-clone body (`Deadlock<Name>MissingBody`, its own asset id) whose `portraitIcon` is a red "!" drawn in code (no
     Deadlock art), plus a `SurvivorDef` with an `UnlockableDef` (`DeadlockOfRain.Missing.<id>`) that is never granted. Two
     patches: `UserProfile.HasSurvivorUnlocked` prefix (always false for it, whatever the profile says) and
     `SurvivorIconController.Rebuild` postfix (keeps the icon white instead of the locked black, title "<Name>: not
     available" in red, hover body = the reason plus `BuiltWith.Versions()`). The placeholders live in
     `MissingHeroes.Bodies/Defs/Unlockables`, never in `Survivors.Bodies/Defs`, so the bench, test mode, co-op cycling,
     equipment and the mod-list entry don't see them. A hero is skipped when it is in `DeadlockCache.Failed` **or** its cache file is missing.
   - **Versions (v0.7.2, `Runtime/BuiltWith.cs`):** `built-with.txt` beside the DLL (`ror2=<Steam build>`, `deadlock=<ClientVersion>`,
     `date`, `version`, written by `tools/package.py`) is read first thing in `Awake`. This PC's RoR2 Steam build comes from
     `steamapps/appmanifest_632360.acf` next to the game; its Deadlock build from `ready.json`. Logged as "Built with ... ;
     this PC: ...". `BuiltWith.Versions()` (built with / this PC, plus "your Deadlock is older/newer" when the ClientVersions
     differ) is appended to every problem message: the skipped-hero box, "heroes missing", the Thunderstore extractor failure and the red "!" hover.
   - **Melty loading summary (v0.7.2):** on a Melty start with a skipped hero, `FirstRun.ShowSummary` (from `Plugin.OpenCache`)
     opens the same `FirstRunOverlay` box with "N of M heroes ready", one line per released hero (`ready` / `NOT AVAILABLE (why)`)
     and the versions, for about 12 s. Nothing is shown when every hero loaded.
   - `new Harmony("melty.deadlockofrain").PatchAll(assembly)` applies every `[HarmonyPatch]` class: `LanguagePatch`, `StatsPatch`, `DamagePatch`, `DebuffResistPatch`, `LoadoutSkinRowPatch`, `MissingHeroes.LockPatch`, `MissingHeroes.IconPatch`, `Equipment.FirePatch`, `Equipment.ClientFirePatch`.
   - `ContentManager.collectContentPackProviders += add => add(new DeadlockContentProvider())`.
   - `Equipment.Init()` subscribes `CharacterBody.onBodyStartGlobal` (starting equipment) and `Run.onRunStartGlobal`.
   - `Buffs.InitHooks()` subscribes the Infernal Resilience heal-back. The other buff effects live in the Harmony patches.
   - `DeadlockAudio.Init()` loads `sounds.json` and starts the mixer thread.
   - `MeltyTest.Init()` activates only if `%LOCALAPPDATA%\Melty\test\risk-of-deadlock-2.json` (Melty's, named after the listing slug) or `deadlock-of-rain.json` (written by our tools) exists.
2. **`DeadlockContentProvider.LoadStaticContentAsync`**, during RoR2's content loading. If `FirstRun` started the
   extractor, it first yields while the process runs (the loading bar follows `progress.txt`, up to 45 % of our share),
   then `FirstRun.Finish`, `Plugin.OpenCache()` and `DeadlockAudio.Init()`. Only `Survivors.Released` heroes are built:
   the ids in `heroes.txt` beside the DLL (a Thunderstore release) or every row (Melty, dev). If the cache is ready it runs
   `Survivors.Build()` (an IEnumerator, stepped while reporting progress), then adds to the `ContentPack`:
   `bodyPrefabs`, `survivorDefs`, `skillDefs`, `skillFamilies`, `entityStateTypes` (every non-abstract EntityState in our
   assembly), `buffDefs` and `equipmentDefs` (built at the end of `Survivors.Build` by `Equipment.Build`). `GenerateContentPackAsync` copies it. RoR2 then assigns catalog indices itself.
   (`ContentPack.identifier` is internal, so the provider's `identifier` property returns the plugin GUID.)

## 4. Building a survivor (`Survivors.Build` → `BuildBody`)

### 4.1 Shared setup
- **Commando:** load `RoR2/Base/Commando/CommandoBody.prefab` by Addressables (`.WaitForCompletion()`).
- **Material template:** `RoR2/Base/Commando/matCommandoDualies.mat`, whose shader is **`Hopoo Games/Deferred/Standard`**. Unity's Standard shader is stripped from the game build, so `Shader.Find("Standard")` gives nothing usable and every hero material is a `new Material(Template)`.
- **Commando's height:** the mesh height if it is between 1 and 3 m, else the capsule height. At 1.5.0 this is the **capsule = 1.820 m**, because the SMR bounds read 0. Then `GlobalScale = CommandoHeight / anchor.sourceHeight = 1.82 / 2.413 = 0.7542`.
- `Buffs.Create()` (BuffDefs) and `Fx.Preload()` (all effect prefabs).
- KinematicCharacterController.dll is not in `ror2-decomp`. Its private `CapsuleHeight/CapsuleRadius/CapsuleYOffset` names were read with `ilspycmd -t KinematicCharacterController.KinematicCharacterMotor <Managed>/KinematicCharacterController.dll`.
- **Prefab holder:** an **inactive** `DontDestroyOnLoad` GameObject `DeadlockOfRainPrefabs` holds every body and display prefab. Instantiated clones are active, but prefabs never run `Awake` themselves.

### 4.2 The body: a Commando clone
`Instantiate(CommandoBody, holder)`, named `Deadlock<Name>Body`. Then:
1. **Network id:** `NetworkIdentity.m_AssetId` is set (reflection) to an MD5 of `DeadlockOfRain.<bodyName>`, so the clone gets a stable, unique asset id, the same on every player's PC: that is how a joined player's game spawns the host's hero (and the other way round) in co-op.
2. **Model swap:**
   - Build the hero model (§4.3) and parent it to `ModelLocator.modelBaseTransform`, at the old model's local position.
   - `DestroyImmediate` Commando's model, and set `ModelLocator._modelTransform` (private) to the new one.
   - `CharacterModel.body = cb`, and every hurtbox's `healthComponent = hc`.
   - `CharacterDirection.modelAnimator = null`.
   - Remove `AimAnimator`s: Commando's Mecanim aim layers don't exist on our model.
3. **Identity and stats** (`stats.json`):
   - `baseNameToken`, `subtitleNameToken`, `portraitIcon` (cache image `imageSmall`), `bodyColor`
   - `base*` and `level*` values for max health, regen, damage, armor, attack speed and crit
   - move speed, jump power and count, acceleration, shield, `sprintingSpeedMultiplier`

   Level growth is **RoR2's own**: `RecalculateStats` computes `base + level*(lvl-1)`. That's why the test can check `maxHealth == base + levelMaxHealth*(lvl-1)`.
4. **Size** (`heightScale`, `widthScale`; v0.7.0 adds `capsuleFrom`, `cameraFrom`, `cameraScale`, `cameraRight`, `interactRange`):
   - `capsuleFrom` (Mo & Krill: `ToolbotBody`): the capsule is **copied** from that vanilla body (loaded as `RoR2/Base/<name minus Body>/<name>.prefab`), so a huge model moves like MUL-T and fits wherever MUL-T does. Otherwise:
   - The capsule height, radius and centre are scaled. The private `KinematicCharacterMotor.CapsuleHeight/CapsuleRadius/CapsuleYOffset` fields are set by reflection, because the motor caches them.
   - `aimOriginTransform` Y is scaled.
   - `CameraTargetParams.cameraParams` is cloned with `idealLocalCameraPos × lerp(1, heightScale, 0.8)` and `pivotVerticalOffset × heightScale`,
     or, with `cameraFrom`, cloned from that body's (MUL-T's); then `idealLocalCameraPos × cameraScale` and `x + cameraRight` (Mo: 1.15, 1.2 m right, so the crosshair is not on his back).
   - `Interactor.maxInteractionDistance × interactRange` (Mo 1.6: he reaches chests from the edge of his body).
5. **Skills:** see §7. Commando's four `GenericSkill`s get one family each.
6. **Passive:**
   - `SkillLocator.passiveSkill` is a struct: copy it, set it, and assign it back.
   - It is enabled when `heroes.passiveName != none`, with tokens `DLR_PASSIVE_<ID>` / `DLR_PASSIVEDESC_<ID>` and the icon from `passiveIcon`.
   - It shows on character select. The *mechanics* live in the gun's on-hit code (§7.4).
7. **Components added:** `DeadlockHero` (id tag), `UltController`, `HeroRuntime`.

Then the display prefab is `ModelBuilder.Build(hero, forDisplay: true)`: no hurtboxes, parented to the holder.

The `SurvivorDef` gets:
- `cachedName = Deadlock<Name>`, `bodyPrefab`, `displayPrefab` (sort position continues at 100.1 + 0.1 per hero, so the next hero is 100.5)
- tokens `DLR_NAME_*`, `DLR_DESC_*`, `DLR_OUTRO_*`, `DLR_FAIL_*`
- `primaryColor`, and `desiredSortPosition` (100.1–100.4, placing them after the vanilla roster)

### 4.3 The model (`ModelBuilder.Build`)
- **Root:** `mdlDeadlock<Name>`, `localScale = GlobalScale × modelScale` (v0.7.0; 1 for the first four, Mo & Krill 1.262 to reach Abrams' height). `<Name>` is the display name in letters only (`Survivors.CodeName`: "Mo & Krill" → `MoKrill`, so bodies are `DeadlockMoKrillBody`: the bench parser and console want one word).
- **Material filter:** `Build(hero, forDisplay, onlyMaterials)` keeps only parts whose material name contains it (`rider`: just Krill, for Tag Team's pickup figure and the flying Krill). The hierarchy is root → `Armature` → bones (from DLM, local TRS) and root → `DeadlockMesh_<material>` renderers.
- **One `SkinnedMeshRenderer` per material/submesh**, all sharing the bone array (`rootBone = Armature`, `updateWhenOffscreen = true`), each with one `CharacterModel.RendererInfo`.
  **Why:** RoR2's `CharacterModel` keeps **one material per renderer** and re-applies `defaultMaterial` every update, so a multi-material renderer only ever drew submesh 0 and the heroes looked invisible or partial.
- **Materials** (`MakeMaterial`):
  - Clone the Hopoo template.
  - Disable keywords containing `LIMB`, `SPLATMAP`, `FLOWMAP`, `VERTEX`, `FORCE_SPEC` or `SKIN`. They expect mesh data (vertex colors, limb masks) Deadlock meshes don't have.
  - `_LimbRemovalOn = 0` and `LIMBREMOVAL` off: otherwise vertices disappear.
  - `_MainTex` = the cached albedo, `_Color` = the material color.
  - Normal, emission and fresnel textures cleared, `_Smoothness 0.2`.
  - Alpha mode ≠ opaque → `_EnableCutout 1`, `CUTOUT` keyword, `_Cull 0` (two-sided).
  - Mesh vertex colors are white (`DeadlockCache.Parts`) because the Hopoo shader multiplies by them.
- **ChildLocator** (private `transformPairs` set by reflection):

  | Name | Bones (the first one found wins) |
  |---|---|
  | `MuzzleRight` | `weapon_hand_R`, else `hand_R` |
  | `MuzzleLeft` | `weapon_hand_L`, else `hand_L` |
  | `Head` | `head` |
  | `Chest` | `spine_2` |
  | `Pelvis` | `pelvis` |
  | `HandR` / `HandL` | `hand_R` / `hand_L` |

  `BulletAttack.muzzleName` and `Fx.Muzzle` use these.
- `DeadlockAnimator.Setup(...)`, then `CharacterModel` (`baseRendererInfos`, `autoPopulateLightInfos`).
- **Hurtboxes** (not on display models), on layer `entityPrecise`:
  - The main one is a capsule of the hero's `sourceHeight` (model space, so ×GlobalScale in the world), radius `0.3·height·widthScale/heightScale`, with `isBullseye`.
  - The head one is a 0.18 sphere on `head` with `isSniperTarget`.
  - Both go in a `HurtBoxGroup` with `mainHurtBox` = the capsule.
- **Death ragdoll (v0.6.1, `BuildRagdoll`, not on display models).** The creator: "on death have a ragdoll". Vanilla
  survivors get theirs from Commando's `DeathState` calling `RagdollController.BeginRagdoll`; our bodies are Commando
  clones, so they only needed the controller on the model:
  - each bone in the animations sheet's `ragdollBones` (pelvis, spine_1, spine_3, head, upper/lower arms and legs; all four
    heroes share Deadlock's skeleton) goes on layer `ragdoll` with a kinematic `Rigidbody` (mass 5), a disabled
    `CapsuleCollider` from the bone to the next listed bone below it (or its farthest child; the head, with no real child,
    gets a ball 0.6× its parent's length), radius `ragdollThickness` (0.3) × that length, and a `CharacterJoint` to the
    nearest listed bone above it (twist ±30°, swing 50°/40°, projection on);
  - `RagdollController` on the model root with those bones and `componentsToDisableOnRagdoll = { DeadlockAnimator }`;
  - `DeadlockAnimator.OnDisable` (only when the body is dead): stops and disables the Legacy `Animation`, parents a welded
    `gunBone` (Abrams' `weaponPivot`) to the hand so the gun falls with it, and switches off the hurtbox colliders riding
    on the bones so they don't join the ragdoll's physics. The `death` clip stays as the fallback if no ragdoll was built.
  - Co-op: the death state runs on every machine, so every player sees the body fall (local physics, as vanilla).

---
- **Cloth bones (v0.3.0):** Deadlock exports cloth bones (`$cloth_*`, ~170 on Abrams' coat) without a parent. Left as
  roots they stayed put while the body moved, so the coat stretched toward a fixed point. `ModelBuilder.Build` attaches
  each one to the nearest bone in the animations sheet's `clothParents` (Abrams: pelvis, spine_0–3), keeping its rest
  pose, and `DeadlockAnimator.BuildClips` skips their tracks. The coat now moves rigidly with his hips and spine (no cloth simulation).
- **Muzzles (v0.3.0):** the `ChildLocator`'s `MuzzleRight`/`MuzzleLeft` point at the animations sheet's `muzzle`/`muzzleLeft`
  bones, the end of the gun (`muzzle_fx` for everyone, `muzzle_fx_L` for Haze's second SMG), falling back to the hands.
  Tracers (`BulletAttack.muzzleName`), muzzle flashes (`Fx.MuzzleFlash` → `EffectManager.SimpleMuzzleFlash`, parented to
  the muzzle so they move with the gun), Bullet Dance's bursts and thrown abilities all start there.

## 5. Scale: the rule and the numbers

**Rule:** one global factor maps Deadlock metres to RoR2 metres, chosen so the **anchor hero (Haze) is exactly
Commando's height**. Every hero uses the same factor, so Deadlock's relative sizes are kept.

| Hero | `sourceHeight` (m, Deadlock) | `heightScale` = h / 2.413 | `widthScale` | RoR2 height (×0.7542) | RoR2 analog |
|---|---|---|---|---|---|
| Haze | 2.413 | 1.000 | 1.0 | ≈1.82 m (= Commando) | Commando |
| Abrams | 2.927 | 1.213 | 1.3 | ≈2.21 m | Loader |
| Seven | 2.43 | 1.007 | 1.0 | ≈1.83 m | Artificer |
| Infernus | 2.505 | 1.038 | 1.05 | ≈1.89 m | Engineer |
| Mo & Krill | 2.319 (× `modelScale` 1.262) | 1.213 | 1.55 (hurtbox; capsule = MUL-T's) | ≈2.21 m, ≈1.9 m wide | MUL-T |

- The **model** always uses `GlobalScale`.
- The **capsule, camera and aim origin** use `heightScale`/`widthScale`.
- Test check `hero-scale` verifies `capsule.height == Commando capsule × heightScale` and `model scale == GlobalScale`.

How `sourceHeight` is measured is in doc 01 §6.3. It is *not* the extract.log height.

## 6. Animation and the gun rig (`DeadlockAnimator`)

### 6.1 Clip playback
- **Legacy `Animation` component** (not Mecanim). The clips are built at runtime from DLM tracks (`SetCurve` on
  `localPosition.*` / `localRotation.*`, linear tangents via `AnimationUtilityLite`), cached per hero, and added with `AddClip`.
- **Root motion removed:** position curves of the root and `root_motion` bones are skipped.
- **`Init()` runs on every clone** (Awake/OnEnable). `Instantiate` does **not** copy private fields, so the animator rebuilds its state (clip map, bones, rig capture) on the display model and on every spawned body.
- **Logical names map to clip names** from `animations.json`:
  - Locomotion (layer 0, looping): `idle`, `run_n/s/e/w`, `sprint`, `jump_air`.
  - Gestures (layer 1, upper body from `upperBodyBone` = `spine_0` via `AddMixingTransform`): `reload`, `secondary`, `utility`, `land`, `jump_start`.
  - Overrides (layer 2, full body, timed or looping): `utility_loop`, `ult_start`, `ult_loop`, `ult_end`.
  - `death` plays on layer 3, clamped.
- **Locomotion choice** (`Update`): airborne → `jump_air`. Otherwise velocity in the model's frame picks N/S/E/W, sprint when sprinting forward, and playback speed is `|v| / moveSpeed` clamped to 0.6–1.8.
- **`fire` and `fire_alt` are `none` on purpose.** The heroes' `shoot_idle*` clips are additive layers that, even composed, point the guns about 60° at the floor and pull Abrams' gun 1.7 m from his hand. Measured with `tools/dlm_pose.py`.
- **`land` is `none` for Haze, Abrams and Seven:** their `jump_landing` clips are partial layers that crush the pose.

### 6.2 The gun rig (sheet columns `gunArms`, `gunBone`, `gunHand`, `aimPose`)
User requirement: the gun is locked to the hand, the gun hand always points where the camera aims, and there is no animation on the gun-carrying arm.

**Capture (`CaptureRig`, at init):**
- Sample `aimPose` (`weapon_stand_idle`) at t = 0 with `AnimationClip.SampleAnimation`, then record:
  - **Arm bones:** everything under `clavicle_R` (and `clavicle_L` when `gunArms = LR`), minus the gun's own bones. Local pose stored.
  - **Gun parts:** everything under `weapon_hand_R/L`, plus everything under `gunBone` except `gunBone` itself. Local pose stored.
  - **Weld offset:** for `gunBone` (Abrams' `weaponPivot`), its position and rotation in `gunHand` space.
  - **Gun forward:** `gunFwdLocal` = the hand→`muzzle_fx` direction in hand space, falling back to the model forward.

**Each `LateUpdate`, after the Animation has written the pose:**
1. **Arm weight:** `armWeight` blends to 0 over 0.15 s while the arms are "free" and back to 1 otherwise. Free means dead, an `Override` clip playing, or within the length of a recent arm-using `Gesture` (anything but `land`/`jump_start`, i.e. reload and ability clips).
2. **Rigid arms:** arm bones are lerped to the captured pose by `armWeight`.
3. **Frozen gun parts:** gun parts are **always** set to the captured pose. Ability clips would otherwise slide the gun inside the hand.
4. **Aim** (only with an `InputBankTest` and `armWeight > 0`):
   - The target is `inputBank.aimDirection`, the camera aim, clamped to ±70° yaw and ±80° pitch from the body's facing (`ClampAim`).
   - For `spine_1`, `spine_2`, `spine_3` with shares ⅓, ½, 1, recomputing every step:
     - **yaw:** rotate about world up by the share of the remaining yaw delta
     - **pitch:** tilt about the gun's own horizontal right axis by the share of the remaining pitch delta
   - Splitting yaw and pitch avoids the roll that `FromToRotation` caused (the torso twisted sideways when aiming down).
   - Everything above `spine_3` turns rigidly, so **two-handed grips stay together**.
   - `AimError` = the final angle between the gun forward and the aim (test check `gun-aims` requires ≤ 8°; measured 0.0–0.1°).
5. **Recoil:** `Recoil(deg)` kicks `spine_3` up by `deg·e^(−t/0.05 s)`. `GunState.FireOne` calls it with 9° for pellet guns and 3° otherwise.
6. **Weld:** `gunBone.position/rotation = gunHand × offset`, always.
7. **`GunDrift`** = the largest change of the gun root (`gunBone`, else `weapon_hand_R`) in hand space, in metres. Test check `gun-in-hand` requires ≤ 2 cm; measured 0.0.

| Hero | gunArms | gunBone | gunHand | aimPose |
|---|---|---|---|---|
| Haze | LR (dual SMGs) | none (guns under `weapon_hand_R/L`) | hand_R | weapon_stand_idle |

| Mo & Krill | R, **`rigPrefix` `rider_`** | none (the gun is part of Krill's mesh, under `rider_weapon_hand_R`) | rider_hand_R | weapon_stand_idle |

### 7.4 Passives and buffs (`buffs.json`, `heroes.json`, `Content/Buffs.cs`)
- **BuffDefs** are created from the sheet: `name`, `buffColor`, `canStack`, `isDebuff`, `isHidden`, icon from the cache. They are registered in the content pack.
- **Stacking passives go through `Buffs.Stack(owner, victim, buff, crit)`** (from the gun's on-hit and Lightning Ball's shocks):
  - a hit adds 1 stack, a **crit adds `critStacks`** (Fixation: 3, standing in for Deadlock headshots), refreshing at `maxStacks`
  - records who applied it (for `damageTakenFromOwnerPerStack`) and applies `withBuff` too
  - **the trigger** fires when the stacks reach `triggerStacks`: with `triggerClears` the stacks are emptied first (Static, Afterburn), without it it fires again every `triggerStacks` stacks (Fixation at 20 and 40)
  - the trigger: `triggerDamagePct` to the victim plus up to `triggerTargets` enemies within `triggerRadius` (proc 0.5, `WeakPoint` color), `triggerStun`, `triggerBuff` on each, and the vanilla Burn when `dotDamagePct` > 0; a flash and arcs in the buff's color
- **`Buffs.Apply(owner, victim, buff)`**: a one-stack debuff, refreshed, owner recorded, `withBuff` applied (Napalm → Napalm Slow).
- **The four passives:**

| Hero | Passive | How |
|---|---|---|
| Haze | **Fixation** | gun `buff` = `fixation`: +2.5 % damage from Haze per stack (max 40, 6 s), crits add 3, every 20 stacks 200 % + `fixation_slow` (12 % for 2 s) |
| Abrams | **Infernal Resilience** | `heroes.damageHealBack` 0.1 / `damageHealBackTime` 10: `HealBack` (event on `onServerDamageDealt`) heals back 10 % of every hit he takes over 10 s, in 0.25 s pulses. `heroes.debuffResist` 0.2: `DebuffResistPatch` (prefix on the private `CharacterBody.AddTimedBuffInternal`) shortens timed debuffs on him by 20 % |
| Seven | **Capacitor** (icon: Deadlock's Tesla Bullets item) | gun, Lightning Ball and Power Surge arcs `buff` = `static` (max 10, 5 s): at 10 the stacks clear, 300 % to the target and 2 enemies within 12 m, all stunned 1 s |
| Mo & Krill | **Heavyweight** | `heroes.immuneToForce`: `HeroRuntime.Start` gives the body vanilla `RoR2Content.Buffs.ImmuneToPhysicsForces` (server), which `HealthComponent.TakeDamageForce` and `RadialForce` respect; jump pads and his own moves still move him. `riderBone` (`rider_pelvis`) is scaled to 0 while a `melee` buff is on (Krill away), every frame on every machine |

| Viscous | **Gooey** | every goo hit's `buff` = `gooed` (`Buffs.AddStacks`, max 5, every stack refreshes all to 3 s): −8 % move and attack speed per stack (bosses half). `heroes.noFallDamage` (`IgnoreFallDamage`). `heroes.landShake` 0.2 (others 2): the landing shake in `HeroRuntime` is a tenth (creator, 2026-10-20). `heroes.gooMaterials` (`viscous_head`) and `glassMaterials` (`viscous_glass`): `ModelBuilder.GooPart` re-makes a part weighted wholly to one bone in that bone's space and draws it as living cel goo (`Vfx.GooPart`, `CelGoo.Gel`) or a clear glossy helmet (`CelGoo.Glass`) instead of the game material; effect-model meshes stay readable (`DeadlockCache`, `UploadMeshData(false)`) so CelGoo can re-colour them | `heroes.voiceGain` 1.2: his voice lines 20 % louder (`Voice.Play`, × the usual 1.15). |
- **`StatsPatch`** (Harmony postfix on `CharacterBody.RecalculateStats`) sums each active buff's columns (× stacks when
  `canStack`), then:
  - multiplies move speed by `1 + moveSpeedAdd` when positive, and **divides** by `1 − moveSpeedAdd` when negative (like vanilla slows). So a true *x* % slow needs `moveSpeedAdd = −(1/(1 − x) − 1)`: Napalm Slow is −0.389 (28 %), Fixation Slow −0.136 (12 %).
  - `slowResist` (Flame Dash 0.5): when slows have pulled the speed under the unslowed base speed (× sprint), that fraction of the gap is given back
  - multiplies attack speed by `1 + attackSpeedAdd`
  - adds armor
  - adds `regenAdd × (1 + 0.2·(level − 1))`
  - adds `maxHealthAdd` × stacks to max health (v0.7.0, Tag Team's trophies)
- **v0.7.0 buff columns:** `disarm` (Buffs.Apply also adds vanilla DisableAllSkills for the duration), `noGun` (the gun can't fire), `melee` (M1 punches, the rider hides), `maxHealthAdd`. `AddTimed` with duration 0 adds a permanent stack.

  The private property setters are invoked through `AccessTools.PropertySetter`.
  - **Hard-coded vs generic:** the stat columns, `damageTakenFromOwnerPerStack`, `critStacks`, `trigger*`, `withBuff` and `slowResist` are generic. The `cloak` column is unused (Smoke Bomb adds vanilla Cloak because its buff id is `smoke`); Bullet Dance evasion reads `evasionChance` of the `bullet_dance` row.
- **`DamagePatch`** (Harmony prefix on `HealthComponent.TakeDamage`):
  - Bullet Dance evasion (`evasionChance`, rejects the hit).
  - Every buff with `damageTakenFromOwnerPerStack` (Fixation per stack, Napalm once): + that much damage when the attacker is the one who applied it (`Buffs.OwnerOf`).

### 7.5 The ultimates as equipment (`Content/Equipment.cs`, `design/equipment.json`)
Since v0.4.0 the Deadlock ults are RoR2 **equipment** (Q). There is no charge meter any more.
- **`Equipment.Build`** (end of `Survivors.Build`) makes one `EquipmentDef` per `equipment.json` row:
  - `cooldown` = the skill row's `cooldown` (120 s, preflight-checked); Fuel Cells and Gesture of the Drowned work as on any equipment
  - `canDrop`, `enigmaCompatible`, `canBeRandomlyTriggered` (Bottled Chaos) from the row, like the **Preon Accumulator**, so RoR2's own
    `RuleCatalog` / `Run.BuildDropTable` put them in the chest and Equipment Barrel pools for **every survivor**
  - icon: the skill's Deadlock icon; tokens `DLR_EQUIP*` ("Haze's Bullet Dance", `pickupText`, the skill description, `lore`)
  - **pickup model:** `PickupModel` builds the hero's display model, samples its idle clip, bakes every `SkinnedMeshRenderer` (`BakeMesh`)
    into one static, centred mesh with one submesh per material. `PickupDisplay` sizes it by that renderer's bounds and spins it:
    a little figure of the hero (creator's pick).
- **Starting equipment:** `onBodyStartGlobal` (server) gives a player's Deadlock hero its own ult on the first stage, once per player per run
  (`given`), only when the slot is empty. Swap it for another equipment and it stays on the ground for anyone.
- **Firing:** RoR2's own Q input and charge/cooldown logic. `FirePatch` (prefix on the private `EquipmentSlot.PerformEquipmentAction`) answers
  `true` for our defs, so RoR2 spends the charge, starts the cooldown and runs War Horn/Bottled Chaos as usual.
  - The state must start where the body has **authority** (a server `SetState` is ignored by an authority client). So the prefix calls
    `Equipment.Fire` right away when the server owns the body (host, drones and other AI, Bottled Chaos), and `ClientFirePatch` (postfix on the
    `RpcOnClientEquipmentActivationRecieved` ClientRpc) calls it on a remote client that owns its body.
  - `Fire` finds the kind's machine (`MachineFor`; falls back to `Weapon`, then any machine on bodies without it), creates the state with
    `RowOverride = row` and `SetInterruptState(PrioritySkill)`; false (no charge spent) when the machine is busy with something that outranks it.
  - Any body can fire any ult: no `DeadlockAnimator` (null-checked), muzzle falls back to the aim origin, `UltLeap` needs a `CharacterMotor`.
  - **Sounds, effects and voice come from the item's row, not the body:** the ult states call `DlrState.Sound(moment)` / `Vfx.Play(row.Vfx, …)`
    with `row` = `RowOverride`, so any carrier plays the ult's `sounds.json` row and `effects.json` moments; `Fire` then calls
    `Voice.SkillLine(row)` for a local player, so the item's hero speaks (§8). Test check `ult-any-survivor` covers it on Commando.

### 7.6 Balance targets (from `skills.json` about + preflight)
- **Sustained primary DPS** (magazine and reload included, computed by preflight from the row) must match `targetDps` ±10 % and sit in **240–600 %/s**. Commando's Double Tap is about 400.
  - Haze 280, Abrams 508, Seven 250 (48 % per bullet since v0.3.0, because Capacitor adds about 30 % per hit on top), Infernus 255.
- **Known mismatch, Seven:**
  - Preflight times a burst cycle as `interval + (burst−1)·duration`.
  - `GunState` re-arms the next burst `interval` after the burst *starts*, so the real cycle is just `interval` (0.2625 s).
  - Seven's real sustained gun DPS is therefore about **350 %/s** (before Capacitor), not 250. It is still inside the band, but stronger than the sheet says.
  - Fix either the preflight formula or the gun's re-arm timing (doc 03 §10).
- **Cooldowns:** the targets are secondaries 2–15 s, utilities 4–12 s and specials 4–30 s (Seven's v0.4.1 cooldowns, 16/16/30 s, are past the secondary and utility targets on purpose: the creator chose cooldowns over damage cuts to bring him into the band). **Preflight only checks that they are > 0.**
- **Equipment ults:** cooldown exactly 120 s and **at least 6000 %** per enemy (dance and zone: duration/interval × damagePct per target; the rest damagePct). That is the Preon Accumulator (8000 % blast plus its lightning on a 140 s cooldown) scaled to 120 s: about 6800 %. There is no upper limit since v0.4.1: the ults are pickups any survivor can carry, so they are left out of balance (creator's decision).
- **`extra` flags:** besides an effects row, `extra` can be a behaviour flag for one kind: `pierce` (kind `projectile`) or `shockwave` (kind `heavy_melee`). Preflight checks the pairing.
- **Stats** are anchored to RoR2 analogs (see `stats.json`): Abrams is Loader-like (160 HP +48/lvl, 20 armor, 2.5 regen), Haze and Seven 110 HP +33, Infernus 130 HP +39. Damage is 12 +2.4 for everyone.

### 7.7 Co-op (v0.6.0, `Runtime/Net.cs`)
Up to 4 players (RoR2's own lobby and Steam invites, plus Melty's Join). Every player needs the mashup at the same version
and their own Deadlock install (their PC builds the heroes from its own cache; the content is identical because the
sheets are).

**Who runs what.** RoR2 networks every skill state: it starts on the hero's owner, is sent to the server, and the server
sends it on to everyone else, so `OnEnter`/`FixedUpdate`/`OnExit` run on every machine. Rules the states follow:
- Sounds, our visuals and animation are played **in the state**, so every player gets them with no networking.
- Damage, stuns, buffs, knockback and stacks are **server only** (`Server`, and inside `Fx.Hit/Blast/Stun/Knock*` and `Buffs.*`).
- Movement, aiming, `BulletAttack`, skill-stock refunds and ending the state are **owner only** (`isAuthority`).
- **RoR2 does not send a player's aim to the server**: there a joined player's body looks straight ahead. The owner's aim
  at the start of a skill (`OwnerAim`) travels with the state, and throws (dagger, ball, flask) and Shoulder Charge's
  start use `ThrowDir` (the live aim on the owner, `OwnerAim` elsewhere). Found when a joined Infernus' Napalm never landed.
- Anything the owner decides at the start travels **with the state** (`OnSerialize` runs after `OnEnter` on the owner,
  `OnDeserialize` before `OnEnter` everywhere else): the ult row (`RowOverride`), the lock-on target of Phantom Strike and
  Haymaker (`LockTarget`, a `HurtBoxReference`, picked by `LockOn()`), Static Charge's point and the body it sticks to.
- Tag Team (R since the play-check) locks on in the owner's state: no target, the owner refunds the stock and nothing is thrown
  (the server's copy of the state has no target either, so it throws nothing); with a target the state carries it to the
  server's hopper. The hops are picked on the server and drawn everywhere through the relay (moment `hop`).
- A move steered by the owner (Shoulder Charge, Flame Dash) reads its direction elsewhere from how the body moves (`MotionDir`).
  Seismic Impact's dive starts on the owner's Left Click; elsewhere it shows as the body dropping fast (`Falling`), and the
  server slams when it sees him land (or when the owner's state ends). Haymaker punches on each machine when that machine
  sees him reach the target, so the server's hit lands a moment after the owner sees it.
- `Projectiles.cs` objects are created by the state on **every** machine with `damage = Server`: each player sees their own
  copy of the dagger, ball, flask and storm fly the same path; only the server's copy hits. Thunderhead's strikes are picked at
  random, so the server picks them and relays them. Torment Pulse's `PulseAura` likewise runs everywhere and damages on the server.

**The relay** (`Relay.*`). For code that runs on the server alone (stack triggers' flash and arcs, the gun's per-hit build-up
visual, Shoulder Charge's hit sparks, Power Surge's sound, Thunderhead's strikes, the Afterburn ignition sound) and for a
joined player's gun shots and reloads: one `EffectDef` of ours (`DeadlockOfRainRelay`, `VFXAttributes.DoNotPool`,
priority Always) is spawned with `EffectManager.SpawnEffect(index, data, transmit: true)`. RoR2 delivers a transmitted effect
to every player exactly once (the host through its local connection, the sender locally), and `RelayFx.Start` plays what the
`EffectData` encodes, then destroys itself:
- `genericUInt` = kind (4 bits: Vfx, Sound, Impact, Flash, Bolt, Shot, Reload) | moment (4 bits, an index into
  `Relay.Moments`) | the row's index in `EffectRow.All` or `SoundRow.All` (same order on every PC);
- `origin`, `start` (+ `genericBool` "has a target point"), `scale` (radius), `genericFloat` (angle or life), `color`,
  `rootObject` (the body to follow).
Never call `Relay` from code that already runs on every machine, or each player gets it twice (or four times).

**Guns.** The owner fires the bullets (RoR2 sends their damage to the server) and plays the shot (`GunState.ShotFx`: sound,
flash, muzzle visual, recoil), then relays it: other players' machines run `ShotFx` too; the owner skips its own relay.
The **on-hit passive** (Fixation, Static, Afterburn build-up) and **Power Surge's arcs** run on the server in `GunHits`,
from `onServerDamageDealt` (damage source `Primary`, inflictor = the hero), the same for every hero whoever owns it. Power
Surge arcs at most once per gun interval (the old "once per burst" flag lived in the owner's state, which the server
doesn't have for a joined player). Firing breaks Smoke Bomb on the server (`BreakSmoke`, from the relayed shot for a joined Haze).

**Equipment ults.** Already written for this (§7.5): the server spends the charge; the ult state starts where the body has
authority and is networked from there.

**Joining.** `Net.RegisterModList` (end of `LoadStaticContentAsync`) adds `melty.deadlockofrain;<version>;<built hero ids>`
(e.g. `...;0.7.0;haze,abrams,seven,infernus`) to `NetworkModCompatibilityHelper.networkModList`, so RoR2's own mod check
refuses a player with another version, without the mashup, **or with other heroes built** (another release's hero list,
or none because Deadlock is missing: bodies and equipment are numbered by catalog position, so such a player would
otherwise join a game that disagrees on what each body and item is). The BepInEx log prints the entry. `MeltyJoin` is Melty's contract
(`%LOCALAPPDATA%\DeadlockOfRain\melty.log` and `melty.properties`):
- the log is emptied at start; whenever this player owns a Steam lobby (Multiplayer, Host), it writes
  `Melty join address: <lobby id>.steamlobby` (one line per lobby);
- with `join=<address>` in melty.properties, once the title screen is up it runs `steam_lobby_join <id>` (or `connect ip:port`
  for an address with a port), then writes `Melty joined: <address>` once connected to the host's game with 2+ players, or
  `Melty join failed: <why>` after 90 s.
Steam invites and RoR2's lobby work as in vanilla; the Melty line is an extra way in.

## 8. Text, UI and audio

- **`LanguagePatch`** (prefix on `Language.GetLocalizedStringByToken(string)`) answers any `DLR_*` token from `Survivors.Tokens`, in every language: names, subtitles, descriptions, lore, outro/fail, skills, buffs, passive, `DLR_SKIN_DEFAULT`.
- **Survivor description** (`DLR_DESC_<ID>`): lore + one line per skill (`M1/M2/Shift/R (Ultimate)`) + the "starts locked… press R" note.
- **`LoadoutSkinRowPatch`** is a postfix on `LoadoutPanelController.Row.FromSkin` (a public static method of the private nested `Row` class). The loadout panel always builds a skins row and its gamepad navigation indexes it. Our heroes have no `SkinDef`s, so an empty row threw `ArgumentOutOfRange`. The patch adds one "Default" button with the hero portrait.
- **Voice lines (`Runtime/Voice.cs`, rows in `design/voice.json`):** Deadlock dialogue for the **local player's** hero,
  played 2D through `DeadlockAudio` as the cache events `vo:<group>`.
  - **select:** once per stage, 2 s after the hero's body starts (`CharacterBody.onBodyStartGlobal`), at run start and on
    every new world after a teleport; not on respawns.
  - **unselect:** `TeleporterInteraction.onTeleporterFinishGlobal`, when leftover gold turns into experience and the
    player is about to leave.
  - **skill:** `onSkillActivatedAuthority` on the local body; the row's own line plays with its `chance` and after its
    `gap`.
  - **ult equipment:** `Equipment.Fire` calls `Voice.SkillLine(row)`, so the **item's hero** speaks, whoever fires it.
    Commando firing Seismic Impact says an Abrams line.
  - **multikill:** kills within 1.5 s of each other; the highest `kills` threshold reached (4 / 7 / 10 →
    killstreak start / mid / high) plays once per burst.
  - **idle:** after 2–5 min (random) without a line from the hero, a `hunt` or `happy` line.
  - Lines never overlap (`DeadlockAudio.IsPlaying`). Select, unselect and ult lines cut off a line in progress; others
    wait their turn.
  - The pages and README never list the lines (creator: "it can be a surprise to players").
- **`DeadlockAudio`:** RoR2 uses Wwise and **disables Unity audio**, so `AudioSource` is silent. Instead:
  - A background thread feeds Windows **waveOut** (44.1 kHz stereo, 4 × 20 ms buffers) from a software mixer.
  - Events come from the **cache's** `sounds/sounds.json` (not `design/sounds.json`, which only names the events per skill). One random variant is played.
  - Each event's own `volume` (a linear gain the extractor converts from Deadlock's decibels since extractor 1.2.0) is clamped to 0.2–2.
  - **Distance:** full volume up to 10 m, then linear fade to 0 at 100 m from the camera.
  - **Pan:** `dot(direction, camera.right) × 0.6`.
  - Distance and pan are computed **once when the sound starts**, so loops don't follow a moving source.
  - At most 25 voices; the oldest is dropped.
  - **Shutdown** (v0.7.3): `Plugin.OnDestroy`/`OnApplicationQuit` call `DeadlockAudio.Shutdown()`, which stops the loop and
    **joins the thread (up to 0.5 s)** so `waveOutReset/Unprepare/Close` finish and the buffers are freed before the process
    exits (also on `Application.quitting`; logs "Deadlock audio stopped"). Before 0.7.3 it only cleared a flag.
    The crash on quit after a run (ntdll c0000005, 0.7.2/0.7.3) was not the mixer: it is RoR2 + BepInEx's console
    writers looping at quit; fixed in 0.7.4 by `Runtime/QuitSafety.cs` (§12 gotcha 22).
  - **Master volume** = `volume_master/100 × volume_sfx/100` (RoR2 convars, re-read once per second), × config `Audio/Deadlock sound volume`, × 0.55, and 0 when the window is unfocused.
  - Guns play their `cast` sound per shot, but never their `hit` sound; the Afterburn ignite uses `infernus_gun.hit`.
  - **Layers and gain** (v0.5.1): a `design/sounds.json` row's `castLayer` / `hitLayer` event plays together with its `cast` / `hit` (a heavier sound under it: Infernus' gun has Warden's shot, Haymaker Abrams' charge-into-wall thud), and `gain` multiplies every event of the row (`Play(..., gain)`); the mixer hard-clips the sum.
  - **Fuse ticks** (v0.6.2): `tick` / `tickFinal` are a countdown played once a second through a fuse and the last one before it goes off. `Fx.Sound` returns the voice id so the state can cut the final tick at the blast. Only Concussive Combustion uses them (Rat King's `Ratking.ScrapGrenade.Timer` / `.Timer.Final`; Deadlock's own fire bomb has just a cast and an explosion).
  - **Test check `sound-events`** (v0.6.2): every event the sound sheet names is in the cache (catches a cache not re-extracted after a new event).
  - `Play(event, pos, loop)` returns an id for `Stop(id)`. The `Played` counter is logged by the test.
- **Effects** (`effects.json`) are RoR2's own prefabs by Addressables key, e.g. `RoR2/Base/Commando/TracerCommandoDefault.prefab`. Prefabs with an `EffectComponent` go through `EffectManager.SpawnEffect` (scale = radius when `scaleWithRadius`). Others are instantiated and destroyed after 3 s. Ghost prefabs (dagger, lightning orb, Napalm's `flask`) have their `ProjectileGhostController` and colliders stripped. Kinds `attachment` (Mired Urn) and `ward` (Warbanner) are RoR2 objects the skill kinds spawn themselves. Check any new key against `tools/dev/addressable_keys.txt` (preflight does).

## 10. Test mode (`Runtime/MeltyTest.cs`)

Active only while `%LOCALAPPDATA%\Melty\test\risk-of-deadlock-2.json` or `deadlock-of-rain.json` exists (Melty writes it during `test_release`; a
hand-written copy works for local runs). The JSON's `"checks"` value is the file to append lines to:
`pass <name>` or `fail <name>: <why>`.
An optional `"heroes": "infernus"` (`run_test.sh infernus`, v0.6.3; also the co-op test) plays only those heroes: the run
starts as the first of them, `ragdoll` counts them, `ult-any-survivor` runs only when Infernus is among them, and the summary

## 12. Gotchas we hit (read before debugging)

1. **One material per renderer:** see §4.3. Symptom: hero invisible or missing parts.
2. **No Standard shader:** clone the Hopoo material. Symptom: pink or invisible.
3. **Limb removal and vertex-color keywords** hide Deadlock meshes: turn them off.
4. **`Instantiate` doesn't copy private fields:** every MonoBehaviour that caches state must rebuild it in `Awake`/`OnEnable` on clones.
5. **Additive clips** crush the pose: compose in VRF (doc 01). Some clips (`shoot_idle`, `jump_landing`) are still unusable alone, so set them to `none`.
6. **Root motion:** runs drift metres per loop, so root position curves are skipped.
7. **Empty skins row** crashes the loadout panel: `LoadoutFix`.
8. **No Unity audio:** use `DeadlockAudio`.
9. **Abrams' gun hangs off the root**, not the hand: weld it.
10. **Aim raycasts must skip your own hurtboxes** (entityPrecise layer includes the caster): Static Charge and Seismic Impact.
11. **Test-mode flakiness** comes from the stage: random first stage, slopes, and monsters wandering in. Use the arena reset and `QuietStage`.
12. **The Melty app turns BepInEx off between its own launches** (`winhttp.dll` → `winhttp.dll.melty-off`). For a manual dev launch, copy it back to `winhttp.dll` (`tools/dev_run.sh` does). Delete the copy afterwards so the folder is the way Melty left it.
13. **Steam must be signed in** for launches. A "Sign in to Steam" window blocks `steam://run/632360` silently.
14. **Runtime particle systems:** a new `ParticleSystem` starts playing; `Stop(true, StopEmittingAndClear)` it before setting `main.duration`, or Unity logs an error and ignores it (`Vfx.Particles` does).
15. **Effects on the ground:** flat `LineRenderer` circles float through the air on slopes and, with RoR2's tracer material, short dashes render as glowing blobs. Ground markers use particles emitted from a circle's edge, or RoR2's `matAreaIndicatorIntersectionOnly` dome, which draws only where it meets the ground. A dome with the rim material tints the whole screen when the camera is inside it.
16. **Negative `moveSpeedAdd` divides** speed: write the slow you want as `−(1/(1 − x) − 1)` (§7.4).
17. **Equipment states run where the body has authority:** starting an EntityState from `PerformEquipmentAction` (server) works only for bodies the server owns; a remote player's state must be started on their client (the activation ClientRpc), with the row id serialized so the server's copy deals the damage.
18. **RoR2's `mat_dust` is opaque** (v0.7.0): big or many dust particles hide the screen (Dust Devil's first build was a brown wall). Keep them small, few and light-coloured; dark tints (or the unlit side) turn into **black blobs** (Burrow's first dirt and Dust Devil on Commando in v0.7.0b); use `mat_smoke` for volume.
20. **Additive lines vanish on snow and sand** (v0.7.0b, Sand Blast's cone): a ground marker that must read everywhere uses an alpha-blended material (`Vfx.Solid`, Unity's sprite shader).
21. **Hiding or moving a model: offset `modelLocator.modelBaseTransform`**, not the model; ModelLocator copies the base's position to the (detached) model every frame (Burrow's sink and rise).
19. **A display name with spaces or `&` breaks the bench parser** (`\S+` body names): object names use `Survivors.CodeName` (letters only).
22. **Crash on quit after a run (ntdll c0000005 at ntdll+0x4a612; fixed in 0.7.4 by `Runtime/QuitSafety.cs`).** It happens
    with our mod switched off too (`OFF=mod VANILLA=1 tools/quit_test.sh`), on any setup with plain BepInEx 5 (Melty's):
    - RoR2's `UnitySystemConsoleRedirector.Redirect()` (at start) saves `Console.Out`, which under BepInEx is already
      BepInEx's `LoggedTextWriter`; `Disengage()` (in `RoR2Application.OnApplicationQuit`) calls `Console.SetOut` with it.
      BepInEx's `ConsoleSetOutFix` turns that into `loggedTextWriter.Parent = <a synchronized wrapper of itself>`, so the
      next console line during Unity's final `CleanupAllObjects` (an OnDisable/OnDestroy) recurses until the main thread's
      1 MB stack overflows. Player.log then shows `LoggedTextWriter.WriteLine` ↔ `SyncTextWriter.WriteLine` repeating.
    - Mono's stack-overflow recovery thunk (`restore_stack`, pointer at mono-2.0-bdwgc.dll+0x757488) starts with
      `push rbp`, so it runs 8 bytes off alignment; the CRT's first `SetThreadStackGuarantee` lookup goes through the
      Steam overlay's `LoadLibraryExW` hook into ntdll, whose aligned `movaps` faults. That is the native crash players see.
    - Fix: a Harmony prefix skips `Disengage` (it only restores the console of a process that is ending), and the thunk's
      `push rbp` is replaced by a nop after checking the exact bytes (from RiskofThunder's RoR2BepInExPack, MIT, which
      r2modman players always have; Melty doesn't install it). Thunderstore players with the pack: the thunk is already
      patched ("already applied"). Test-mode switches `OFF=consolefix` / `OFF=soefix`.
    - Hardening after a security review (2026-10-20): the patch runs only on the verified Mono build (PE SizeOfImage
      0xA54000 + TimeDateStamp 0x66FD8CF6, read from the loaded module's header via GetModuleHandle), and only after
      VirtualQuery shows the thunk is committed executable memory without a guard page. After a RoR2/Unity update it
      logs "not needed for this Mono build" and does nothing; the console fix alone still prevents the crash.
    - How it was found: crash dumps (`%LOCALAPPDATA%\CrashDumps`), symbols from Microsoft's and Unity's symbol servers,
      then the nop patch turned the native crash into a logged StackOverflowException with the looping trace. RoR2 saves
      the profile synchronously in `OnApplicationQuit` before all this, so players never lost progress.

- **Flat max health from buffs (trophies) and vanilla's heal/clamp (v0.7.1f).** `RecalculateStats` compares the new max health
  with the old one and heals the gain or cuts health above the new max. Our `StatsPatch` adds `maxHealthAdd` in a postfix,
  after that, so vanilla saw every recalculation as a loss and cut health back to the base max. The prefix now records health
  and the max without our add (per body, `lastHealthAdd`); the postfix restores health plus only vanilla's own gain, clamped
  to the new max. A new stack therefore raises the max without healing. Test check `trophies`.
